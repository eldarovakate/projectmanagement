02 Команда

Состав команды в IT-проекте

Ключевой принцип: роли фиксируются в начале проекта. Когда непонятно, кто отвечает — не отвечает никто.

🧭

Project Manager

Отвечает за сроки, коммуникацию и управление рисками. Держит всё вместе.

Сроки, риски, коммуникация, эскалация проблем

📐

Аналитик / BA

Формализует требования, строит мост между бизнесом и разработчиками.

Требования, документация, согласование с заказчиком

🎨

Дизайнер / UX

Создаёт интерфейс, опыт пользователя и визуальную концепцию продукта.

UX-исследование, прототипы, UI-система

⚙️

Backend-разработчик

Строит серверную логику, API, базы данных и интеграции.

Реализация функционала, code review, технический долг

🖥️

Frontend-разработчик

Реализует интерфейс, анимации и взаимодействие с пользователем.

Реализация интерфейса, качество кода на фронте

✅

QA-инженер

Тестирует продукт, ищет баги и следит за качеством на всех этапах.

Тест-кейсы, регрессия, приёмочное тестирование

🛠️

DevOps-инженер

Обеспечивает инфраструктуру, CI/CD и стабильность развёртывания.

Инфраструктура, деплой, мониторинг, CI/CD

👤

Заказчик / Product Owner

Определяет приоритеты, принимает решения и является голосом бизнеса.

Постановка задач, приёмка, ответственность за продукт

Две великие команды — два разных результата. Почему звёзды не всегда выигрывают?

Реал Мадрид, 2000-е — «Галактикос»

—

Собрали лучших игроков мира из разных команд: Зидан из Ювентуса, Роналдо из Интера, Бекхэм из МЮ, Фиго из Барселоны, Роберто Карлос из Бразилии

—

У каждого — своя звёздная история, свои привычки, свой стиль игры и свои амбиции. Никто не привык уступать роль

Результат: в сезоне 2003–2004 при составе из суперзвёзд Реал не выиграл ни одного трофея и вылетел из Лиги чемпионов в 1/8

Вывод: набор лучших специалистов — не команда. Команда — это система, где люди притёрлись, знают роли друг друга и работают на общий результат.

02 Команда

Команда ≠ набор людей

Команда проекта — это группа людей с разными ролями и компетенциями, объединённых общей целью и несущих совместную ответственность за результат.

Набор людей
  • ✕ Каждый работает сам по себе
  • ✕ Нет общей цели
  • ✕ Непонятно, кто за что отвечает
  • ✕ Конфликты не разрешаются
  • ✕ Информация теряется
≠
Команда = система взаимодействия
  • ✓ Синхронизированные цели
  • ✓ Чёткие роли и ответственности
  • ✓ Прозрачная коммуникация
  • ✓ Конфликты решаются внутри
  • ✓ Знания передаются и сохраняются

05 Лидерство

Не бойтесь
брать ответственность

Технические навыки — это порог входа. Лидерство — это то, что определяет масштаб вашего влияния.

🧭

Владейте решениями

Хороший PM не ждёт разрешения. Он берёт ответственность, принимает решение и несёт последствия.

🛡️

Защищайте команду

Когда что-то идёт не так — вы стоите перед заказчиком, не прячетесь за разработчиком.

📡

Говорите правду

Плохие новости не улучшаются со временем. Сообщайте о рисках и проблемах сразу — это признак зрелости.

🌱

Растите людей

Лучший показатель PM — когда команда после проекта стала сильнее, чем в начале.

🔁

Учитесь на ошибках

Пост-мортем без поиска виноватых. Ретроспектива без страха. Провал — это данные, не приговор.

Лидерство — это создание среды,
в которой люди могут делать сильную работу.
